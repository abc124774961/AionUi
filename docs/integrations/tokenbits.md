# AionUi 的可选 TokenBits 连接

AionUi 保留原有名称、标识、工作台、会话、工具和自定义模型提供商。TokenBits 是附加的账号与模型服务连接；可以选择“稍后”，继续使用原有功能。此集成由 TokenBits 添加，不代表 AionUi 官方运营或背书 TokenBits 服务。

网页版沿用 AionUi 原有使用方式与工作台，主要改动是 TokenBits 的深度集成。独立单用户 Web 包只是原有 WebUI 的交付形式；本次不提供新的公共托管平台，也不承诺跨设备同步。

## 使用范围

| 形态           | 本次支持范围                                                                                                                       |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 桌面           | 原生 AionUi 工作台中的可选连接，设备授权、账户与钱包余额、模型配置、断开连接                                                       |
| 独立 Web       | 不启动 Electron 的原有 AionUi WebUI；使用自身登录会话，供一个受信任用户使用                                                        |
| 共享多租户托管 | **未交付**；未完成用户之间的文件、工作目录、工具进程和执行环境隔离，不能把 WebUI 登录或 TokenBits 账户隔离当作完整的多租户安全边界 |
| 模型能力       | 首批按 OpenAI 兼容聊天路径集成；不据此宣称所有模型的图片、工具调用、上下文或其他能力都已验收                                       |

TokenBits 登录用于授权模型服务，AionUi WebUI 登录用于访问工作台，两者用途不同。共享主机上的文件和工具仍受主机权限与原有工作台能力约束。

## 连接、配置与使用

1. 从原有欢迎页、设置或侧栏的 TokenBits 入口打开连接面板。选择“稍后”不会阻止继续使用 AionUi。
2. 点击连接后自动打开 TokenBits 浏览器连接流程。已登录时自动完成授权；未登录时先正常登录，然后自动继续。新版流程不显示设备码，也无需再次点击批准。原有设备码链接仍保留手动确认，不能通过打开任意链接自动批准。
3. 桌面版自动打开浏览器一次并查询连接状态；Web 版在当前标签页往返，回调立即清除短期回执，并验证发起标签页与原 AionUi 账户。成功后返回原工作台并打开模型配置。取消、过期或网络失败后不会自动反复重连。
4. 连接成功后查看账户和钱包余额，选择服务档位与模型，再点击配置。配置动作不会发送模型请求，也不会替换当前会话使用的模型。
5. 在 AionUi 原有模型选择器中选择新增的 TokenBits 托管模型，再主动发送对话。其他已配置提供商仍可使用。

授权请求的范围为读取账户、读取目录、管理模型连接和撤销本设备。设备访问凭证、刷新凭证与模型密钥由 AionUi Core 处理，浏览器中的连接 UI 不接收这些凭证。界面仅打开 Core 返回的可信 HTTPS 发行方同源地址。Web 回调绑定 HttpOnly Cookie、一次性回执、state 与 PKCE；远程 HTTPS Web 部署需由 TokenBits 运营方配置精确回调 origin 白名单，不能直接信任任意自托管地址。

钱包余额并非套餐剩余额度或最终费用估算。余额加载失败显示“暂不可用”，不显示为零。配置模型不代表免费使用；价格、套餐适用范围及实际计费以 TokenBits 价格页与账单为准。

## 断开、撤销与切换账户

- 在 AionUi 中断开连接会停用对应的 TokenBits 托管模型并清除其凭证，不删除原有会话、历史记录或其他提供商配置。
- 也可以在 TokenBits 的个人设置中查看 AionUi 设备，并确认撤销单台设备。多 Gateway 的撤销缓存可能需要约 30 秒收敛；已建立的流式连接不会因此强制中断。
- 如果 AionUi 提示撤销尚未确认，本地状态会保留，不能视为已断开。请到 TokenBits 设备页确认撤销后重试，不要把网络失败提示理解为远端撤销成功。
- 切换 TokenBits 账户前先断开，再重新授权。账户与模型目录的缓存按 AionUi 用户、发行方和设备区分；新设备加载时不会显示上一设备的账户余额与模型目录。
- 需要重新授权时，重新连接并选择模型。现有会话记录仍保留；失效的托管模型需要换用可用模型后才能继续请求。

## 独立单用户 Web 部署

使用与此集成配套、包含 TokenBits 路由的 Core 二进制；仅安装一个普通上游 Core 版本号不能证明它支持此功能。`AIONUI_BACKEND_BIN` 可显式指定已验证的二进制。源码启动需要仓库声明的 Node.js 版本、Bun 和依赖。

```sh
bun install
bun run package
AIONUI_BACKEND_BIN="/absolute/path/to/aioncore" \
  bun run webui:prod --no-build --no-open
```

`bun run package` 仅编译 main、preload 和 renderer，不生成安装包。上述 Web 命令使用已编译资源；首次启动按终端提示使用初始账户登录，然后修改初始密码。默认仅本机访问，生产模式默认端口为 `25808`。

独立 Web 的默认生产数据目录为 `~/.aionui-web`，开发目录为 `~/.aionui-web-dev`，与桌面默认目录分开。可以用 `--data-dir` 或 `AIONUI_DATA_DIR` 显式选择数据目录；为不同实例使用独立目录。停止时使用 Ctrl+C，让 WebHost 和 Core 一起正常退出。

WebHost 启动自己的 Core 时使用 `--identity-mode webui`，桌面使用本地身份模式。远程访问请沿用 [WebUI 指南](../guides/webui.md) 和 [服务器部署指南](../guides/deploy-server.md)，为一个受信任用户配置 HTTPS、工作台认证和主机访问权限。此部署方式不提供共享多租户的文件或执行隔离。

## 构建、更新与发布边界

默认 AionUi 构建保持原有发布与更新路径。TokenBits 增强发行版必须显式设置 `AIONUI_DISTRIBUTION=tokenbits`；该发行版的手动和自动更新使用独立的 `abc124774961/AionUi` 发布源，避免与 AionUi 官方 CDN 更新路径混用。产品身份仍为 AionUi。

源码检查通过、`bun run package` 成功和可分发安装包是三个不同结果。发布安装包时应另外记录版本、源码提交、Core 二进制 SHA-256、安装包 SHA-256、平台架构、签名/公证状态与首次启动结果。未实际构建并验证的平台不应列为可下载发行物。

目前计划的增强发行版本为 `2.2.2-tokenbits.1` 预发布版，目标为 macOS arm64；构建、上传与可下载状态以实际发布记录为准。该目标没有开发者签名与 Apple 公证，不应描述为已签名或已公证。其他平台尚未构建。

## 验收记录与限制

2026-11-10 的客户端完整测试观察到 526 个测试文件通过、1 个跳过；5031 个测试通过、5 个跳过。13 个语言包、字面量翻译键与生成类型的一致性检查通过。后续主进程与打包配置变更需要相应定向检查，不从这些数字推断之后的代码也已验证。

真实 Gateway 与 Core 的本地集成验收覆盖桌面及独立 Web 的设备授权、聊天请求与撤销。该验收的模型上游为本地脚本，证明请求链路与授权生命周期，不证明付费真实模型的可用性、性能或计费结果。浏览器组件验收另使用模拟数据检查桌面与 390px 宽度下的连接、等待、已连接状态及键盘可访问控件；截图中的账户、模型和余额均为测试数据。

最终检查日志、构建结果与源文件哈希保存在本次工作目录的 `output/tokenbits-final-acceptance/`；视觉证据位于 `output/tokenbits-visual/`。这些本地记录不是公开发布物。安装器、系统凭证存储、付费推理及完整原有工作台端到端回归应分别以对应的实际验收记录为准。
